# 最小实验计划

## 目标

验证一条具体结论，而不是“做一个大 Agent”：在固定客服工具环境中，针对一种高频失败进行训练，是否能在独立测试集上提高任务成功率，同时不提高非法操作率和成本。

## 阶段与停止条件

### A. Harness 校准

- `scripted_oracle` 在 dev/test 上成功率必须为 100%。
- 每个写工具至少有一条成功测试和一条政策拒绝测试。
- 同一输入与同一模型设置可以保留完整、可读、可复核 trace。

不满足以上条件时不训练。

### B. Baseline 数据

- 四类意图各准备 30～50 个任务模板，再做实体、措辞、状态组合扩展。
- train/dev/test 按模板族切分，避免只替换订单号造成泄漏。
- 未训练小模型与通用强模型各运行至少 3 个随机种子/采样轮次。
- 人工抽查全部失败样本和至少 10% 成功样本。

输出：失败类型分布、每种失败的代表 trace、五项核心指标。

### C. 选择一个训练目标

默认优先选择 `parameter_error`。只有满足以下条件才训练：

1. 在小模型失败中占比高；
2. 强模型明显更好，说明任务可解；
3. verifier 能客观区分正确/错误；
4. 预计 100～500 条高质量纠正轨迹就能覆盖主要模式。

### D. SFT

- 只把人工验收成功或人工纠正后的轨迹放入训练集。
- 先用 20～50 条做过拟合 smoke test。
- 正式实验保持 base model、推理参数、Harness、测试集完全一致。
- 至少报告：base、SFT、strong 三组结果。

### E. 是否做 GRPO

仅当 SFT 后仍存在“需要根据工具返回动态调整”的重复错误时做 GRPO。先用 8 个单轮任务和 5～10 个优化 step 验证：

- 能产生不同奖励；
- reward 与人工判断一致；
- 非法行为明确为负奖励；
- 没有通过输出格式或重复调用投机取巧。

之后再扩充训练任务，保留独立 test 不参与 rollout。

## 没提升时如何判断

- 训练集准确率也不上升：检查数据格式、LoRA 是否生效、模型容量与学习率。
- 训练集上升而 dev/test 不升：检查样本量、模板泄漏、表达覆盖和过拟合。
- reward 上升但人工成功率不升：奖励可被钻空子或 verifier 有漏洞。
- 成功率上升但非法操作率也上升：奖励对安全约束惩罚不足。
- 强模型同样失败：任务信息、工具返回、政策定义或评测更可能有问题。
- SFT 上升而 GRPO 下降：rollout 多样性不足、组内奖励方差过小或训练不稳定。
