# 本轮结论与下一轮工作

## 已完成及可以支持的结论

在一张RTX 4090 D 24GB上完成Qwen2.5-3B-Instruct的Base → LoRA SFT → GRPO。三个阶段均评测同一批15个开发任务和40个测试任务。测试成功率分别为3/40（7.5%）、8/40（20%）、4/40（10%）。SFT相对Base观察到12.5个百分点提升；本轮GRPO相对SFT下降10个百分点，不能描述为强化学习提高了总体成功率。

教师在官方训练任务上完成118次有效采样，77次任务成功；经格式、工具错误、长度及抽样内容审查，最终选用58条对话、覆盖35个训练任务。并非生产聊天数据，也没有经过全量人工审核。SFT执行2 epochs、116个优化批次，监督目标token共179,614；两个epoch的平均batch loss为0.4715和0.3487。

GRPO执行28组、112条选用轨迹，10轮策略更新对应33个实际优化批次。17组全失败、1组全成功，没有组内奖励差异；只有10/28组（35.7%）产生更新。奖励为任务结果0/1，未使用额外的工具错误、冗余调用或预算惩罚。

## 观察到的问题

1. **预算耗尽更多。** 测试集上，SFT有17/40条失败轨迹耗尽交互预算，GRPO后为23/40。整体平均工具调用从9.75增加到11.575。调用数受任务失败时机影响，这些现象不能单独证明因果，但提示应检查重复查询与结束决策。
2. **改善与遗忘同时存在。** SFT→GRPO有3个任务失败转成功，同时7个成功转失败。任务51恢复成功，任务26却从成功变为上下文超限，见[案例](cases.md)。
3. **训练信号稀疏、覆盖有限。** 大多数组没有有效相对优势。此次SFT只有58条对话，GRPO只有33个优化批次，不足以据此判断更大规模训练的表现。
4. **运行修复带来限制。** GRPO在第6组完成后续跑，保留LoRA权重但重置优化器动量。2次空消息误分类曾触发额外采样，该组最终仍全0且未更新。SFT评测的3个请求错误曾补跑；原错误正文未保存，不能确定其原因。

这是单次环境种子42的结果；采样服务使用模型别名，动态用户对话不保证逐字相同。没有据此检验统计显著性，也没有完整政策违规率、供应商实际费用或线上生产效果。错误尝试、被替代的中断组轨迹和修复记录均保留在原始目录及[过程日志](journal.md)。

## 硬件与工程验证

- 完整保留最长16K上下文，单卡完成实际反向更新。成功SFT运行的5秒采样显存峰值为23,500MiB（约22.95GiB）；正式GRPO为15,250MiB（约14.89GiB）。采样可能漏过瞬时峰值，不能当作更小显存设备的运行保证。
- 修复ART独立SFT路径未恢复Unsloth梯度检查点、RL词表中间量显存积累、Unsloth与PyTorch 2.9检查点签名兼容问题。词表重算的概率、熵和梯度与稠密参考通过数值对照。
- [完整性核验](audit.json)通过：三阶段任务覆盖、训练数据归属、课程顺序/种子、奖励组与检查点0/1/11一致。代码测试与运行验证见[verification.json](verification.json)。

## 下一轮建议（尚未执行）

1. 先固定本轮SFT检查点作为起点，扩展剩余训练任务的成功示范，增加“确认后执行一次、读取结果、正确结束”的针对性样本；验证数据质量，避免仅增加重复表达。
2. 在开发集比较原始0/1奖励与加入重复调用/预算约束的奖励，保持任务成功为主目标，并单独检查业务政策，防止为减少调用而跳过必要确认。
3. 对照较小学习率及对SFT参考模型的KL约束，保存优化器状态后开展不中断训练；这些是待验证假设，不是本轮退化的已证实原因。
4. 以开发集选型，做多种子复验；最后再进行冻结配置的独立测试，必要时增加未参与本轮分析的新任务。当前简历可报告本次SFT结果及GRPO实验与诊断，不宜声称RL带来额外成功率提升。

SFT权重位于`.art/service-agent-retail/models/qwen25-3b-experiment-fast/checkpoints/0001/`，GRPO最终权重位于同目录的`0011/`。它们是LoRA适配器，需要与登记的原始3B模型及本地工具调用模板一起使用，不是独立完整模型。
