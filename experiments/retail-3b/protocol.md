# 单卡客服 Agent 实验协议

日期：2026-10-03。目标：测量同一Qwen2.5-3B-Instruct在工具选择、参数生成与多轮错误恢复方面，经SFT及GRPO后的实际变化；不预设提升。

## 固定条件

- 官方tau零售环境，版本`5bfa7e37b36656b37dc6d022156be6563c1007f3`；59 train / 15 dev / 40 test，沿用已有划分。
- 本地Qwen2.5-3B-Instruct原始权重；ART0.5.16、vLLM0.15.1、PyTorch2.9.1、Transformers4.57.3、OpenAI SDK2.54.0。仅GPU 0（RTX4090D 24GB）。
- 教师/用户/裁判：用户配置的qwen3.7-flash接口；关闭思考。该API是浮动别名，服务端模型快照及完全确定性不能由本项目保证。
- 用户额外采用`visible-identifiers-v1`约束：仅从任务场景和可见对话取得编号，拒绝新编造的邮箱/长编号/邮编并最多重试3次；保存拒绝记录。未读取数据库或标准动作，仍不是全面语义真实性验证。
- 裁判要求JSON，核对断言数量及内容，格式错误最多重试3次；失败属于基础设施/模拟器错误，不能当作RL奖励0。
- 学生上下文16384、单次输出512、temperature=0评测，最多40个交互步骤、5次工具错误；推理最多2个并发序列。所有阶段相同。
- 正式三阶段统一启用CUDA Graph（`enforce_eager=false`）；此前Eager运行只作为性能诊断，结果不混入主表。
- 单次评测seed=42，使用全部15个dev和40个test。单种子实验，不报告统计显著性或稳定提升；test不用于选参数或选检查点。
- 评测使用4个独立环境进程、单GPU最多2个推理序列；环境随机状态互相隔离。

## 执行顺序与预算

1. 训练任务各采样2次（seed42/43），共118个候选教师轨迹。与Base评测并行运行。
2. 筛选训练集内成功、无工具错误、未截断、消息格式正确的轨迹；剔除超过16K的整条轨迹，不截断业务政策或对话，记录排除原因。抽查成功样本的身份/确认/工具参数；审核者为Codex，不能标成人工审核。
3. Base：全dev/test评测，保存原始轨迹和失败分析。
4. SFT：LoRA rank16、alpha32、dropout0，4-bit训练加载，batch1，学习率峰值5e-5，线性调度及10%warmup，2 epochs；记录逐batch loss和训练token数。
5. SFT：使用同一协议评测全dev/test。选取最后一个SFT检查点，test结果不改变本次训练设置。
6. GRPO：仅从训练任务采样，同任务每组4条轨迹，temperature0.7，学习率5e-6，组内标准化相对优势、PPO clipping epsilon0.2、无KL项；官方任务奖励0/1。最多30组，目标10轮有信息组的策略更新（一次ART train调用保存一个检查点，可能包含多个优化批次）；同奖励组不更新，报告真实更新数。允许从成功教师覆盖的训练任务建立课程，必须记录完整ID名单。
7. GRPO：最后检查点评测全dev/test；汇总Base/SFT/GRPO的配对任务结果。不根据测试结果挑选另一检查点。

预算是本次实验上限，不保证每个候选成功。运行故障重试保留记录；硬件/依赖修复和协议变更写入过程日志。若没有有效奖励差异，报告GRPO未获得更新，不能虚构RL改善。

## 结果与证据

主要指标：官方任务成功数/总数、成功率、出现工具错误的任务比例、平均工具调用数、终止原因。另报有效评测覆盖、模拟器/接口错误、token用量、时延、观察到的显存与训练loss。

全面政策违规率和供应商费用当前缺少完整验证器/已核实计价，保持空值。工具错误率不等于政策违规率。所有表格从保存的轨迹计算，保留失败结果。旧部署阶段的3个任务及未约束模拟用户的失败记录不混入本实验。
