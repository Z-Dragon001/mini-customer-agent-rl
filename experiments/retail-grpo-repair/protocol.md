# GRPO 改进实验协议

日期：2026-10-13。目标是在原有 SFT 起点上取得可复核的策略改善，同时区分正则约束和过程奖励的贡献。所有历史结果保留；不预设新的成功率。

## 假设与对照

- 原实验 18/28 个组无奖励差异，10 轮更新后测试成功率从 20% 降到 10%；这些只是原实验观察，不作为新实验结论。
- A（outcome）：从原 SFT step 1 复制权重，学习率 2e-6，官方结果奖励，作为本轮训练基线。
- B（kl）：与 A 相同，增加 beta=0.02、固定 SFT 适配器参考的 KL 正则；验证策略偏移约束的贡献。
- C（shaped）：与 B 相同，增加有界过程惩罚；验证重复调用/错误/预算信号的贡献。
- 每组 4 条轨迹，temperature=0.7，PPO epsilon=0.2；每臂 24 组（96 条），按固定训练任务课程和固定组种子采样。每 8 组评测全部 15 个开发任务，保留所有检查点。
- 课程与旧实验相同，仅包含教师覆盖的 35 个训练任务；不从测试集挑选训练任务，不修改推理提示词和工具环境。
- C 奖励：官方 0/1 结果减去 min(0.3, 0.02×重复调用数 + 0.02×工具错误数 + 0.10×预算耗尽 + 0.10×非法输出)。成功轨迹最低 0.7，失败最高 0，保证结果优先。
- 重复调用只统计相同名称、规范化参数且先前成功的调用；成功的写操作会使读缓存失效。此指标是低效调用代理，不称为全面违规率。
- 所有奖励相同的组跳过更新；C 中全失败组也跳过，避免在完全没有成功依据时只学会短路失败。与 B 的差异整体归为过程奖励方案，不能单独归因给某一个惩罚项。

## 评测与选择

- 相同 Qwen2.5-3B-Instruct、同一 SFT checkpoint、同一官方环境版本和任务划分，单张 GPU 0 RTX 4090 D 24GB。
- 推理上下文 16384，单次生成 512 tokens，40 步、5 次工具错误上限，评测 temperature=0；用户/裁判 API 使用现有配置。
- 先在本轮重新运行 SFT 的开发集；候选模型按开发集成功任务数优先、预算耗尽数其次、重复调用数再次、较早检查点最后排序。
- 每臂按 seed 42 的周期性开发评测选一个候选；再在 seed 43 全部开发任务上与 SFT 比较。两个开发种子汇总按同一规则选择最终 RL 候选，冻结配置和检查点后才运行测试。
- SFT 与所选 RL 模型分别在全部 40 个测试任务上运行 seed 42、43，报告逐种子及汇总成功率、工具错误任务比例、预算耗尽、重复调用和调用开销，保留配对任务变化。
- 旧测试集已用于上轮事后分析，属于已知基准上的后续实验；不把它称为从未查看的新外部留出集。第二种子是评测重复，不冒充多训练种子验证。
- 若开发结果表明方案无收益，先报告证据再制定下一轮训练方案，不能根据测试结果循环挑参数。

## 工程与证据

训练奖励与官方评测奖励分开保存。网络/用户/裁判故障不能作为失败奖励；失败轨迹不因低分而重采样。周期性开发轨迹绝不进入优化器。补齐优化器与 Python/NumPy/Torch 随机状态保存及恢复；记录恢复边界，远端用户仍不保证完全确定。

记录命令、配置、数据/起点权重哈希、每组原始轨迹、奖励分解、梯度/损失/KL、采样组与实际更新数、开发选择和最终评测。训练代码改动先完成关键单元/集成检查，正式训练中首次 KL 更新验证其有限性和实际执行。

本轮工作目录：`experiments/retail-grpo-repair/`；原始轨迹：`traces/retail/grpo-repair/`。计划、实际变更和故障按时间记入 `journal.md`。

## 训练期间的方案修订：数值一致性对照

在KL臂完成、尚未运行任何本轮测试集之前，代码与启动日志确认采样端BF16、训练端4-bit；同时发现打包的input_pos未传递给模型。前三臂设置保留，再增加D（consistent）：与C相同的KL/奖励/任务/种子/预算，训练基座改为BF16，概率归一化使用FP32，并传入打包位置编号。该组检验数值一致性修复的整体贡献；不把其效果单独归给三个子改动中的某一个。所有新增组仍按相同开发规则选型。

为量化偏差，后续训练记录采样旧概率与训练新概率的MAE、偏差和超出PPO裁剪区间比例，同时保留首个训练输入批次。KL臂已结束，无法补录其逐批概率诊断；其他前三臂只增加观测，不改损失或数学。

增加测试门槛：四臂完成后，只有候选在两个开发种子合计成功数严格超过SFT，才进行冻结测试。否则停止在开发结果并据此设计下一轮，不通过测试集循环调参。

## 测试前追加 E：可执行业务进度奖励

在 D 的第16组开发结果出现退化之后、尚未查看本轮测试集之前，对A/B训练轨迹做严格离线重放：A的16个全失败组中9组、B的15个全失败组中12组存在业务进展差异，二值奖励丢弃这些学习信号。新增E（progress），与D相同的原SFT起点、BF16/FP32/packed位置、KL、学习率、任务顺序、种子及24组×4条预算。前三次开发检查和第二开发种子规则均不变，候选池扩展为五组。

E的训练奖励 = 官方0/1成功 + 0.15×目标读操作覆盖率 + 0.25×目标写操作覆盖率 + 0.10×DB目标达成 - 有界过程惩罚。动作按官方任务定义匹配参数，并额外要求对应工具响应成功；每个目标动作只计一次。DB项仅用于有目标写操作的任务。附加奖励最高0.5，过程惩罚最多0.3，故最差完整成功0.7仍高于最佳失败0.5。任务目标只在轨迹结束后的训练奖励计算中使用，不进入模型输入；开发和测试仍只用官方成功判定。

E允许全失败组在业务进度有差异、且总奖励有差异时更新；仅有调用开销差异而没有业务进度差异时跳过。E相对D是“进度奖励及其组筛选规则”的整体对照，不把其效应分别归给每一项。新的组是在测试前根据训练/开发证据追加；开发集较小且候选增多，最终测试仍须披露选择偏差及统计不确定性。
